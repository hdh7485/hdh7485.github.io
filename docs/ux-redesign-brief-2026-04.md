# hdh7485.github.io UX Audit and Redesign Brief

작성일: 2026-04-05
작성자: UXDesigner

## 목표

- 홈, 퀴즈, 결과, 신뢰 페이지에서 이탈을 줄이고 다음 클릭을 늘린다.
- "무료, 빠름, 익명"이라는 핵심 가치를 첫 화면과 결과 화면에서 더 분명하게 전달한다.
- 페이지마다 제각각인 스타일과 흐름을 공통 컴포넌트로 정리해 Web Engineer가 반복 구현하기 쉽게 만든다.

## 검토 범위

- 홈: `index.html`
- 대표 퀴즈: `mbti-pokemon-quiz/index.html`, `travel-destination-quiz/index.html`
- 추천형 도구: `lunch-roulette/index.html`

## 상위 5개 UX 문제

### 1. 홈이 너무 많은 선택지를 한 번에 밀어 넣어서 첫 클릭이 약하다

현재 홈은 상단 소개, 토픽 카드, 우선 탐색 링크, 긴 설명 리스트, 대형 카드 그리드가 한 페이지에 모두 겹쳐 있다. 사용자는 "지금 무엇을 눌러야 하는지"보다 "뭐가 이렇게 많지?"를 먼저 느끼기 쉽다. 특히 인기 콘텐츠, 카테고리, 설명형 카피가 같은 시각적 무게를 가져서 스캔 우선순위가 약하다.

문제 예시

- 홈 상단에 4개 토픽 카드, 우선 탐색 링크, 긴 소개 리스트, Top 6 리스트가 모두 공존한다.
- 카드 수가 많아지는데도 featured 영역과 catalog 영역이 분리되지 않는다.
- 홈 hero에 단일 primary CTA가 없다.

권장 변경

- 상단을 `Hero + 대표 3개 카드 + 카테고리 레일` 3단 구조로 단순화한다.
- Hero에는 "무료 / 3분 내외 / 익명" 신뢰 배지를 고정 배치한다.
- "지금 가장 많이 하는 테스트" 한 줄과 "가볍게 게임 시작" 한 줄을 분리한다.
- 긴 설명형 리스트는 접거나 하단 "이 사이트 소개" 섹션으로 내린다.

### 2. 대표 퀴즈 시작 화면과 질문 화면이 공통 UX 셸 없이 흩어져 있다

페이지마다 질문 카드, 진행 표시, 버튼, 타이포가 제각각이다. 가장 심한 사례는 MBTI 포켓몬 페이지로, 현재 `../harry-potter-house-quiz/index.html`을 스타일시트처럼 연결하고 있어 의도한 기반 스타일이 안정적으로 적용된다고 보기 어렵다. 대표 퀴즈가 흔들리면 사이트 전체 신뢰감이 떨어진다.

문제 예시

- MBTI 포켓몬은 잘못된 stylesheet 연결에 의존한다.
- 어떤 퀴즈는 시작 화면이 있고, 어떤 퀴즈는 바로 질문으로 들어간다.
- 질문 수, 예상 소요 시간, 익명 처리 안내가 CTA 근처에서 일관되게 보이지 않는다.
- 버튼 크기와 옵션 선택 피드백이 페이지마다 다르다.

권장 변경

- 모든 퀴즈에 공통 `QuizShell` 레이아웃을 도입한다.
- 시작 화면에는 반드시 `질문 수`, `예상 시간`, `결과 성격`, `개인정보 비저장` 4개 정보를 넣는다.
- 질문 화면 상단은 `진행률 + 현재 질문 번호 + 한 줄 설명`으로 고정한다.
- 모바일에서 CTA가 화면 아래로 멀어지지 않도록 옵션 선택 직후 다음 버튼을 같은 뷰포트 안에 유지한다.

### 3. 결과 화면이 끝점처럼 보이고 다음 행동을 충분히 만들지 못한다

결과를 본 뒤 사용자가 취할 수 있는 행동이 대부분 "다시 하기" 수준에 머무른다. 추천형 테스트와 결과형 테스트에서 결과 자체는 괜찮아도, 공유, 재방문, 다음 콘텐츠 탐색으로 이어지는 구조가 약하다.

문제 예시

- MBTI 포켓몬 결과 화면은 사실상 재시작 버튼 하나만 제공한다.
- 여행지 추천 테스트는 공유 버튼이 있지만 결과 저장, 유사 테스트 이동, 홈 복귀의 우선순위가 정리되어 있지 않다.
- 결과 페이지에서 "왜 이 결과가 나왔는지" 요약 근거가 약하다.

권장 변경

- 모든 결과 페이지를 `ResultHero + 해석 포인트 + 추천 행동 + 관련 콘텐츠` 구조로 통일한다.
- 버튼 우선순위는 `결과 공유`, `비슷한 테스트`, `다시 하기` 순서로 재정의한다.
- 결과 설명 아래에 "이런 답변 성향 때문에 이 결과가 나왔어요" 한 줄 근거를 추가한다.
- 관련 콘텐츠는 2~3개만 노출하고, 현재 결과와 연결되는 이유를 짧게 붙인다.

### 4. 신뢰/정책 페이지는 정보는 많지만 안심을 주는 구조가 약하다

연락처와 개인정보처리방침은 텍스트 양이 많고 구조가 길다. 홈과 퀴즈에서 사용자가 궁금해하는 "이 사이트는 안전한가?", "문의는 가능한가?", "결과는 저장되나?"에 대한 답이 도착 지점에서만 길게 나온다. 이 정보는 trust page에만 있으면 늦다.

문제 예시

- `contact.html`은 이메일 문의 유도는 되지만 FAQ형 빠른 답변 구조가 약하다.
- `privacy.html`은 첫 줄 요약은 괜찮지만 문서 전체가 길고 탐색 요소가 없다.
- 개인정보처리방침 페이지의 viewport 메타가 잘못 작성되어 있다.
- trust 정보가 홈/퀴즈 CTA 근처에 재사용되지 않는다.

권장 변경

- 모든 퀴즈 시작 화면과 결과 화면에 `익명 진행`, `회원가입 없음`, `결과 비저장` trust strip을 삽입한다.
- `contact.html` 상단을 "빠른 문의 방법 / 응답 시간 / 어떤 내용을 보내면 좋은지" 3카드 구조로 축약한다.
- `privacy.html`은 상단 요약, 쿠키/광고, 결과 저장 여부, 문의 경로의 4개 앵커 섹션으로 재구성한다.
- 정책 페이지용 공통 서브헤더와 요약 박스를 만든다.

### 5. 시각 시스템과 컴포넌트 규칙이 없어 페이지 품질이 랜덤하게 보인다

현재 사이트는 페이지별로 폰트, 배경 그라디언트, 버튼 반경, 카드 그림자, 정보 박스 톤이 모두 다르다. 개별 페이지만 보면 큰 문제는 없어도, 사이트 전체 경험은 하나의 브랜드보다 여러 개의 템플릿 모음처럼 느껴진다.

문제 예시

- 어떤 페이지는 시스템 폰트, 어떤 페이지는 `Malgun Gothic`을 사용한다.
- 버튼 radius, 카드 shadow, 타이포 스케일이 페이지마다 다르다.
- 결과 카드와 정보 섹션이 페이지별로 전혀 다른 컴포넌트처럼 보인다.

권장 변경

- 최소한의 디자인 토큰을 만든다: 색상, spacing, radius, shadow, heading scale, CTA size.
- 페이지별 accent color는 유지하되 레이아웃/타이포/버튼 형태는 공통화한다.
- 공통 스타일은 `shared/` 아래 퀴즈 셸과 trust components로 분리한다.

## 재사용 컴포넌트 제안

### 1. Hero Trust Strip

- 내용: `무료`, `3분 내외`, `회원가입 없음`, `결과 비저장`
- 위치: 홈 hero, 퀴즈 시작 카드, 결과 카드 하단

### 2. Featured Rail

- 가로 또는 2열 카드로 운영
- 사용처: 홈 상단 대표 콘텐츠, 결과 후속 추천

### 3. QuizShell

- `IntroCard`
- `ProgressHeader`
- `OptionList`
- `PrimaryActionBar`
- `ResultHero`

### 4. Policy Summary Box

- 긴 정책 페이지 상단에 4~5줄 요약
- CTA: `문의하기`, `홈으로`, `관련 페이지`

### 5. Related Content Module

- 제목
- 왜 추천하는지 1문장
- 2~3개 카드

## 엔지니어링 핸드오프 메모

- 이번 단계는 풀 리브랜딩보다 "공통 셸 정리 + 첫 클릭/다음 클릭 강화"에 집중하는 것이 좋다.
- 페이지별 개성을 완전히 없애면 안 된다. 색상과 아이콘 톤은 유지하고, 구조와 컴포넌트만 통일한다.
- 광고 슬롯은 현재 bootstrap 구조를 유지하되 hero와 질문 흐름을 방해하지 않는 위치에서만 노출해야 한다.
- 첫 구현 대상은 `index.html`, `mbti-pokemon-quiz`, `travel-destination-quiz`, `contact.html`, `privacy.html`이 적절하다.
